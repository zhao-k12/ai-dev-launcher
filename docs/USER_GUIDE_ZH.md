# AI Dev Launcher 2.0 中文使用手册

## 开始使用

1. 打开 AI Dev Launcher。
2. 点击“创建新项目”。
3. 输入项目名称并选择保存位置。
4. 点击“创建并进入”。启动器会自动创建目录、初始化 Git、生成 `AGENTS.md` 并准备 AI 环境。

## 与 Codex 对话

- 在中间输入框直接输入中文任务，按 Enter 发送；Shift+Enter 换行。
- Codex 的回复、执行状态、命令和工具结果会显示在会话中。
- 点击“停止”可以终止当前任务及其子进程。
- 继续发送消息会恢复同一个 Codex 会话。
- 左侧会话列表支持新建、重命名和删除；会话按项目独立保存。

## 权限模式

- **标准模式**：默认选项，Codex 使用 `workspace-write` 沙箱，工作范围限制在当前项目。
- **完全访问**：允许跳过沙箱和审批。只应对可信任务使用，界面会持续显示风险提示。

权限只影响启动器创建的当前任务，不会写入用户的全局 Codex 配置。

## 文件、改动与终端

- “文件”显示项目文件树并预览 UTF-8 文本。
- “改动”显示 Git 状态和 Diff。“接受”会暂存文件；“撤销”只适用于 Git 已跟踪文件，并要求确认。
- 启动器不会自动删除未跟踪文件。
- “终端”在当前项目目录运行 PowerShell，显示标准输出、错误输出和退出码。
- “节省”显示 Headroom 已节省 Token、节省比例和代理请求数。

## 自动维护

- Headroom 和启动器私有 Codex CLI 会自动检查并更新。
- 新版本先安装到临时目录，验证成功后才替换当前版本。
- 更新失败会保留或恢复旧版本。
- 用户全局 Codex CLI 和 Codex 桌面端不由启动器管理。

## Codex 桌面端独立性

Codex 桌面端不需要 AI Dev Launcher 才能运行。启动器不会设置系统代理，也不会永久修改 Codex 路由。关闭、强制结束或卸载启动器后，Codex 桌面端仍应正常使用。

## 常见问题

### 环境一直显示正在恢复

打开“环境状态”查看哪项检测失败。启动器会自动重试；Codex 或 Headroom 尚未可用时可等待私有工具更新完成。

### Headroom 出现 WebSocket 403

当前 Codex CLI 会自动回退到 HTTPS。只要最终产生 Codex 回复，对话仍然成功。

### 无法撤销 `??` 文件

`??` 表示未被 Git 跟踪。为避免误删用户文件，启动器不会自动撤销或删除它；可以先“接受”暂存，或在确认内容后通过终端自行处理。

### Windows 提示未知发布者

当前安装包未进行代码签名。请确认安装包来自本项目的 GitHub Release 后再继续安装。
